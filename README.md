# Отчёт по спецпроекту «Ключевые слова»

Ежедневно пересобираемый отчёт по спецпроекту [reklama-keywords.ru](https://reklama-keywords.ru):
прохождение мини-игры, переходы на Авито Рекламу и регистрации в рекламном кабинете.

## Что откуда берётся

| Источник | Что даёт |
|---|---|
| Метрика `111451917` | визиты спецпроекта, воронка мини-игры (7 шагов), клики на Авито Рекламу |
| Метрика `101840084` | трафик, доехавший до Авито Рекламы, и цель `513361195` «Успешная регистрация» |

Трафик спецпроекта на принимающей стороне опознаётся двумя признаками, потому что ссылки
размечены по-разному: `utm_source=landing_ads` для `ads.avito.com` и `from=ads_special_keywords`
в адресе входа для `avito.ru/ads`.

## Как это работает

`build.py` ходит в обе Метрики, считает производные и подставляет данные в `template.html`,
получая готовый самодостаточный `dashboard.html` — весь отчёт одним файлом, без внешних запросов.

GitHub Actions запускает сборку ежедневно в 09:00 MSK и публикует результат.
Можно запустить вручную: вкладка **Actions** → **Отчёт по спецпроекту** → **Run workflow**.

## Локальный запуск

```bash
pip install -r requirements.txt
echo "METRIKA_TOKEN=ваш_токен" > .env
python3 build.py
open dashboard.html
```

Токен — OAuth Яндекс.Метрики с правом «Получение статистики, чтение параметров».
Аккаунт должен иметь доступ к обоим счётчикам. В репозитории токен живёт только в
GitHub Secrets под именем `METRIKA_TOKEN`; локально — в `.env`, который в `.gitignore`.

## Период

Даты кампании зашиты в `build.py` (`DATE1` / `DATE2`) — 10–31 августа 2026.
После 31 августа отчёт замораживается на финальных числах, и ежедневный запуск можно выключить,
убрав блок `schedule` из `.github/workflows/report.yml`.

## Методика

- Атрибуция — последний значимый переход, одинаково во всех разрезах.
- Конверсии считаются по визитам, охват — по посетителям.
- Переходы на Рекламу — уникальные визиты с достижением хотя бы одной из шести целей-кнопок
  (OR-сегмент), а не сумма достижений: простая сумма завышает результат примерно на четверть.
- Внутренние тестовые метки (`test`, `testa`, `testa1`, …) из разреза по источникам исключены.
- Адреса входа схлопнуты до уникальных страниц: query-параметры отброшены, хэш оставлен
  только именем экрана — `#signin` и `#login` это разные состояния, и в них весь смысл.

## Чего в отчёте нет

Понять, какой рекламный канал принёс конкретную регистрацию, по этим данным нельзя:
исходящие ссылки не пробрасывают исходный `utm_source` спецпроекта, на принимающей стороне
все метки одинаковые. Стоимость регистрации считается только в среднем по проекту.
